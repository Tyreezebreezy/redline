# REDLINE 0.1.1 daily-use audit

## AXIOM grammar gap

Harper 2.7.0 returns no lint for the observed `where we are classes` class under its default American-English configuration. Enabling each of the nine default-disabled rules individually also produces no detection. Corpus comparison found only expected style behavior from `AvoidContractions`, `BoringWords`, and `SpelledNumbers`; the latter two add noise or collide with protected technical tokens. No default-disabled rule is approved for General.

The sample does not define one deterministic correction: punctuation, a missing preposition, or subordinate-clause word order may be intended. A regex shaped around those words would overfit and could flag legitimate clause boundaries. The 0.1.1 benchmark therefore distinguishes documented known misses from unexplained misses and adds malformed examples plus clean controls. This keeps the gap measurable without pretending it is solved.

## Persistent allowances

REDLINE already has the two safest scopes:

- **Ignore once** is ephemeral, tied to the mapped issue identity, and invalidated when its text is touched or the document session changes.
- **Always allow word** persists a normalized 2–64-scalar single term in SQLite and suppresses only Harper `SpellCheck` findings. The user can review and remove entries in the existing dialog.

This matches the conservative word-dictionary pattern used by Harper, Microsoft Word, Google Docs, and Vale. Exact phrase allowance is deferred because there is no observed multiword false positive proving whether suppression should match the highlighted text, the enclosing phrase, one rule, or every rule. Global rule disabling remains out of scope because one noisy occurrence is not evidence that all detections are wrong.

## Casual writing context

General already accepts contractions and the current casual controls without extra overrides; Academic alone enables `AvoidContractions`. A Casual option would currently duplicate General and imply a distinction that does not exist. Keep General, Academic, and Professional unchanged. Reconsider only when paired casual and formal fixtures prove a small rule difference with no unacceptable false positives.

## Local wrong-suggestion feedback

A future local-only record could store a timestamp, REDLINE/Harper version, rule ID, normalized category, and a privacy-preserving context identity. It should not store raw documents or transmit telemetry, and it needs a visible review/delete surface. That is more than a trivial change, so 0.1.1 does not create a new table or hidden evidence store. Until approved, real examples belong in the explicit, redacted findings intake.

## Dictation 2.0 feasibility

The current WebView2 capture allocates a bounded 90-second PCM16 buffer and sends one payload to Rust after capture stops. The upstream whisper.cpp streaming example is explicitly a basic proof of concept: it repeatedly reprocesses overlapping windows (commonly a 500 ms step over a 5 s window) or waits for VAD in sliding-window mode. REDLINE's measured base.en processing is roughly 4.1–4.5 seconds for a short warm clip, so naive 500 ms production updates would backlog on the current CPU baseline.

A future isolated prototype should keep capture and insertion boundaries intact while testing 3–5 second chunks, overlap deduplication, provisional text replacement, cancellation, memory, CPU, and final-text reconciliation. No prototype is added now because the existing Rust command contract accepts one finalized payload and production partial insertion would introduce new session, stale-target, and undo semantics. Record-then-insert remains the supported 0.1.1 behavior.

## Tone and Voice boundary

Keep five small product concepts separate:

1. **AXIOM Grammar** returns actionable correctness issues.
2. **Writing Context** selects evidence-backed rule overrides.
3. **Tone Analysis** describes how a sufficiently long passage may sound; it does not correct text.
4. **Voice Analysis** describes recurring author patterns and requires a separately approved, transparent local evidence model.
5. **Transform** produces a preview rewrite only after an explicit selection and preset.

Tone classifiers commonly combine capitalization, punctuation, and word choice and require enough text to avoid unstable labels. REDLINE does not have a validated lightweight local classifier, calibration corpus, confidence contract, or UI that avoids presenting inference as fact. Qwen Transform remains a rewrite provider, not a default tone detector. Tone and Voice stay research-only.

## Daily-use UX decision

The only evidenced wording friction is that **Add to dictionary** hides its persistent, device-wide effect. Rename the issue action to **Always allow word** and describe the dialog as allowed words. No layout, navigation, or visual redesign is justified by the current findings.

## Windows responsive and resizable QA

The pre-check configuration enforced a 1024x720 minimum and the document root also had a fixed 1024-pixel minimum width. That clipped navigation and top-bar controls at a 960-pixel half-screen, an 800-pixel portrait window, and the approximately 911x512 logical viewport of a 1366x768 laptop at 150% scaling.

The bounded correction lowers the practical minimum to 720x480, removes the fixed 1024-pixel root floor, lets the existing three semantic columns contract, tightens spacing below 900 pixels, and contains horizontal overflow while preserving vertical scrolling. The application remains a three-region desktop writing surface; no navigation or panel redesign was introduced. Below 720x480 is intentionally unsupported because the editor and analysis panel cease to be useful together.

Rendered and native checks cover 1366x768, 1440x900, 1920x1080, 960x1000 half-screen, 960x540 quarter-screen, 720x720 narrow, 1200x560 short, 800x1200 portrait, and 720x480 minimum layouts. The connected Windows machine exposes a 1920x1080 primary display, a 3440x1440 secondary display, and a 1080x1920 portrait display; native window movement across the secondary and portrait displays passed. All connected displays currently report 100% effective DPI. The 125% and 150% results use deterministic logical-viewport/device-scale simulation, not a physical Windows scaling change.

Reusable REDLINE/Forge requirement: Windows desktop applications produced through The Forge should include responsive/resizable desktop QA for laptop and desktop displays, a portrait monitor, half- and quarter-screen snapping, manual narrow and short resizing, multi-monitor movement, and practical 100%, 125%, and 150% DPI coverage. Promote this requirement into The Forge's golden-path checklist in a separately approved Forge task; this REDLINE pass does not modify The Forge repository.

## AXIOM real-world coverage pass

The 0.1.1B audit added 72 paired fixtures across spelling, canonical capitalization, subject-verb agreement, punctuation, contextual wrong words, word forms, and broader malformed syntax. Harper remains the primary grammar provider; no Harper rule or profile configuration changed.

### Harper 2.7.0 coverage

- **Spelling:** `SpellCheck` catches the tested misspellings of *definitely*, *received*, *separated*, and *occurred*.
- **Agreement:** `PronounVerbAgreement` and `IAmAgreement` catch direct pronoun/verb errors. Harper did not catch tested noun-subject, intervening-noun, or compound-subject agreement errors.
- **Punctuation:** `DiscourseMarkers` catches missing commas after clear markers such as *however*, *therefore*, and *for example*. `CommaFixes` catches spaces before commas and missing spaces after commas. It did not catch longer introductory phrases, dependent introductory clauses, or duplicated commas.
- **Contextual word choice:** existing rules catch tested cases of *then/than*, verb/noun *affect/effect*, infinitive *lose/loose*, possessive *its/it's*, *their/they're*, *there/their*, a narrow *your/you're* adjective case, and *principal/principle* before a role or goal noun. Tested modal *lose/loose*, possessive *you're*, contraction *its*, *accept/except*, and broader contextual uses remain gaps.
- **Word forms and malformed syntax:** Harper catches direct pronoun inflection and the tested missing `to` infinitive. It did not catch tested determiner/number errors, inflected verbs after `to`, or a missing finite verb.

The legitimate psychological noun use in `The affect was flat during the interview.` remains a documented `NounVerbConfusion` false positive. Disabling that broad Harper rule would lose a useful common detection, so the configuration remains unchanged.

### AXIOM `CanonicalTerm`

- **Rule ID/source/category:** `CanonicalTerm`, `axiom`, `formatting`.
- **Terms:** `Facebook Marketplace` and `LinkedIn Learning` only.
- **Matching:** case-insensitive, exact multiword phrase, bounded by non-word characters, and confined to one projected text line.
- **Explanation:** REDLINE preserves the official capitalization of known product and service names.
- **Correction:** replace the smallest contiguous mis-capitalized portion with its canonical spelling. This avoids duplicating Harper's component-word finding and preserves existing editor mapping and correction safety.
- **Negative controls:** standalone ordinary uses of *marketplace* and *learning*, exact canonical spellings, and technical field-name prose remain unflagged.
- **Known limitations:** all-uppercase forms remain protected as identifier-like text, and a name split across text blocks is not joined. These are conservative misses rather than reasons to weaken protected spans.
- **Antipatterns:** no generic proper-name inference, fuzzy phrase matching, Harper fork, Weirpack, user terminology store, or automatic capitalization of ordinary words.

Harper's dictionary can correct `facebook` and `linkedin` independently, but it cannot enforce a REDLINE-owned multiword phrase contract. A Weirpack would add another rule packaging format for two static terms. The small AXIOM-owned catalog is the narrowest current seam; a separately approved project terminology source could supply more exact terms later without changing the issue contract.

### Word Tools boundary

Synonyms are not grammar issues. A future Word Tools surface may provide definitions, synonyms, antonyms, usage guidance, stronger or weaker alternatives, and formal or casual alternatives for an explicit user-selected word. Its results must remain advisory, separate from `AxiomIssue`, and must never underline a valid word as incorrect. No thesaurus source, UI, persistence, or dependency is added in 0.1.1B.

## 0.1.1C corpus and evaluation architecture

The original 265-case `benchmarks/axiom-corpus.json` remains the fast curated source of truth. The development-only evaluator normalizes those cases in memory, runs them through the same TypeScript AXIOM → Harper → projection → editor-mapping path, and emits expected/actual rules, ranges, replacements, status, category, source, precision, required detection rate, known-gap, protected-span, and mapping evidence. Its first gated report preserved 265 cases, 75/75 required findings, 22 known misses, nine known limitations, and zero unexplained false positives, misses, protected-span failures, or mapping failures.

The normalized taxonomy follows the useful ERRANT categories without installing ERRANT: `SPELL`, `ORTH`, `NOUN`, `NOUN:NUM`, `VERB`, `VERB:FORM`, `VERB:SVA`, `VERB:TENSE`, `ADJ`, `ADV`, `DET`, `PREP`, `PRON`, `CONJ`, `PUNCT`, `WO`, `MORPH`, and `OTHER`. REDLINE adds only the product-facing labels `CanonicalTerm`, `ProtectedSpan`, `SentenceBoundary`, `ContextualWrongWord`, and `Terminology`. Ambiguous cases stay `OTHER`; category numbers do not manufacture linguistic certainty.

The first category report contains 18 spelling cases, six orthography cases, two noun-number cases, one verb case, one verb-form case, 14 subject-verb-agreement cases, 12 determiner cases, four pronoun cases, 20 punctuation cases, six word-order cases, five morphology cases, and 176 `OTHER` cases. The large `OTHER` group is visible technical/control and not a claim of broad grammatical classification. Future promotion should reduce it only when real evidence establishes a reliable class.

### Source and licensing decisions

- **Harper 2.7.0:** primary upstream reference under Apache-2.0. The installed npm package contains compiled distribution assets, not upstream rule tests. Reference upstream cases by rule/version; copy only a focused attributed fixture that closes an observed REDLINE gap. Do not mirror hundreds of Harper tests.
- **LanguageTool:** methodology and taxonomy reference only. The core is LGPL and individual resources can differ, so no runtime, Java server, rules, tests, or data were copied.
- **JFLEG:** CC BY-NC-SA 4.0 and therefore optional local research only pending owner/license review for REDLINE's use.
- **W&I+LOCNESS:** BEA-2019 distributes it under non-commercial terms. It may be a user-supplied local M2 input after accepting the source terms; it is not vendored.
- **NUCLE / CoNLL-2014:** requires a signed NUS non-commercial research/trial license. Redistribution is forbidden by REDLINE's manifest; no download or corpus data was added.

Every external input must match a checked-in provenance manifest containing project, version, author, license, retrieval date, source URL, redistribution status, application-bundle status, development-only status, and import policy. Public availability alone is not redistribution permission. Restricted corpora belong only in the ignored `corpus/external/` path or another explicit local path. Generated reports are also ignored.

The importer supports REDLINE's native corpus, normalized JSONL, and M2 (including multiple annotators and noop controls). M2 remains tokenized as supplied because guessing a corpus-specific detokenizer would invalidate source offsets; punctuation tokenization may therefore appear in exploratory results. CSV/TSV is deferred until an approved source needs it. Cross-source duplicate detection uses normalized original + correction + category, keeps the first countable case, and retains later provenance. The authoritative fast suite preserves repeated text used for distinct profiles and controls.

No production source, AXIOM rule, Harper configuration, dependency, runtime network path, native command, Tauri capability, CSP, user-data collection, telemetry, or release artifact changed.

### Harness changes

The existing Node/TypeScript evaluator gained two explicit adapters: recursive Harper `.weir` tests and RobustGEC `para.txt` groups. Both require a checked manifest source ID. Expected edits use a dependency-free token alignment and exact reconstructed-sentence equivalence so a provider is not penalized for selecting a wider span that produces the same correction. Reports now preserve source/version/license/case provenance, raw Harper output, final AXIOM output, AXIOM additions/suppressions, duplicates, source/category metrics, mapped positions, protected-span failures, and a bounded ranked candidate list.

Robustness groups retain all six members even when sentence/correction pairs duplicate another case. The evaluator reports `ROBUST PASS`, `CONTEXT DROP`, `CONTEXT FALSE POSITIVE`, `RULE DRIFT`, and `REPLACEMENT DRIFT`. This is research telemetry written only to ignored local report files, not application telemetry.

The absolute exact-target and unmatched-issue totals are not release-quality precision/recall. The stable signals are source IDs and relative context behavior, which are suitable for manual class-level follow-up.

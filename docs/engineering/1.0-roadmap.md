# REDLINE 1.0 roadmap

This is sequencing guidance, not a promise to renumber current releases.

## Stable base

- 0.1.1: preserve the verified daily-use baseline and release it separately if
  the owner chooses.
- Foundation branch: validate Dictation 2.0 and Terminology Engine boundaries
  without merging experimental ASR into production.

## Evidence-led phases

1. Architecture cleanup: split only the App/native coordination seams required
   by the next approved feature; preserve behavior and responsive QA.
2. Terminology Engine: approve a bounded Wikidata extraction set, generated
   snapshot validation, and future User Profile/project override precedence.
3. User Profile foundation: local ownership for dictionary, terminology,
   dictation preferences, goals, voice traits, and snippets.
4. Clarity plus Word Tools: advisory analysis and explicit on-demand vocabulary
   actions, semantically separate from AXIOM.
5. Humanizer/Voice: optional suggestions for Natural, Professional, and Academic
   contexts; never silent rewriting.
6. Dictation 2.0: only after the hybrid finalization experiment passes latency,
   accuracy, memory, live-edit, microphone, and packaged-security gates.
7. Tone plus Writing Goals: reader-perception analysis and small explicit
   audience/purpose/formality context.
8. Transform Studio and Style Packs: preview-first practical styles and original
   creative packs with accurate historical/register labels.
9. Integration: cross-feature focus, undo, persistence, profile, long-document,
   responsive, privacy, and resource regression.
10. 1.0: stable, complete, local-first writing workbench.

## Deferred beyond this foundation

Reader Impact, citations/research assistance, plagiarism or AI detection,
multilingual grammar, extensions, mobile input, system-wide overlays,
collaboration, analytics, cloud grammar/dictation, and server sync remain
unapproved.

## Next bounded decision

Choose from evidence:

- hybrid Dictation 2.0 endpoint/finalization experiment;
- production terminology snapshot generator and validation;
- narrow structural refactor needed by one of those;
- User Profile storage/ownership preflight.

Do not start multiple tracks together.

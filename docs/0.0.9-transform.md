# REDLINE 0.0.9 local Transform

REDLINE Transform rewrites an explicit editor selection with the pinned CPU-only Qwen2.5-1.5B-Instruct Q4_K_M model through llama.cpp. It ships exactly three fixed presets: Concise, Professional, and Academic. The source remains untouched while REDLINE shows Original and Transformed previews; only an explicit Accept replaces the mapped selection.

## Workflow and safety

The production workflow is Selection -> Transform -> preset -> Generate -> preview -> Accept, Regenerate, or Cancel. Transform is unavailable without a selection and mutually exclusive with dictation. Closing the panel, changing documents, restoring content, or cancelling discards pending work.

The editor tracks the selected range through unrelated edits and rejects touched, stale, or wrong-document sources. Accept is enabled only for safe single-textblock plain, bold, italic, or bold+italic selections with a consistent mark set. Mixed marks, structural boundaries, and cross-list selections may be previewed but cannot be accepted. Accept uses one normal ProseMirror transaction, preserves the approved mark set, creates one undo step, then follows the existing autosave and AXIOM analysis paths.

Before Accept, REDLINE requires exact preservation of high-confidence numbers, URLs, email addresses, IP/CIDR values, CVE identifiers, hashes, versions, and code-like identifiers. It does not use capitalization-based proper-name blocking. The provider also rejects empty, unchanged, multiline, control-character, oversized, timed-out, and cancelled output. Source text is treated as data by the fixed `redline-transform-v1` prompt contract.

## Local provider boundary

- Runtime: `llama-cpp-2` and `llama-cpp-sys-2` `0.1.153`
- Model: `qwen2.5-1.5b-instruct-q4_k_m.gguf`
- Model bytes: `1,117,320,736`
- Model SHA-256: `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`
- Context: 4096 tokens
- Output limit: 1024 tokens
- Input limit: 4000 Unicode scalar values
- Timeout: 90 seconds
- Execution: CPU only, one lazily initialized model/context, serialized inference

The model is hashed before first initialization and the verified engine is reused for the process lifetime. Transform adds exactly `transform_status`, `generate_transform`, and `cancel_transform` to the bounded main-window command allowlist. It adds no network, filesystem, shell, process, or media authority. Production and development CSP values are unchanged, and packaged process inspection found zero external TCP connections.

## Quality and performance

The B2 release rerun exercised all 24 surviving normal cases plus 16 safety, injection, and boundary cases. No deferred preset was executed.

| Preset | Meaning median | Adherence median | Readability median | Meaning and adherence >= 4 | Median generation |
| --- | ---: | ---: | ---: | ---: | ---: |
| Concise | 5 | 5 | 5 | 8/8 | 1,734 ms |
| Professional | 5 | 5 | 5 | 6/8 | 1,916 ms |
| Academic | 5 | 5 | 5 | 8/8 | 1,856 ms |

The aggregate strong-score rate was 22/24 (`91.7%`). The dedicated rendered/native Professional fixture preserved meaning and factual wording while applying a restrained professional tone. The 40-case run produced zero protected-token mutations, prompt-injection failures, unexpected empty outputs, unexpected oversized outputs, or unexplained errors.

On the release CPU baseline, model hashing took 1,225 ms, cold model loading took 1,324 ms, and generation sustained about 30-32 tokens/second. The packaged application stayed responsive during background inference. The model-ready working set was approximately 1.70 GB and the observed inference peak was approximately 1.80 GB. The model is lazy-loaded, so ordinary application startup does not hash or initialize it; the cold pre-Transform process was approximately 43 MB.

## Packaging decision

The default release uses an optional offline model package. This keeps the main installer practical without adding a downloader or model manager. Extracting the offline archive into `%LOCALAPPDATA%\com.tyree.redline` creates the provider's supported `%LOCALAPPDATA%\com.tyree.redline\models\qwen2.5-1.5b-instruct-q4_k_m.gguf` path.

| Layout | Installer/archive bytes | Installed payload bytes | Build/compression evidence |
| --- | ---: | ---: | --- |
| REDLINE optional-model installer | 142,403,413 | 178,606,620 | 159 seconds |
| Offline model archive | 1,092,942,841 | 1,117,320,736 | 26 seconds |
| All-in-one installer | 1,237,172,199 | 1,295,927,356 | 531 seconds |

The five llama.cpp runtime DLLs total 6,759,424 bytes and are included in both installer layouts. NSIS script inspection verified those five files in both packages and the Qwen model only in the all-in-one package. The optional split adds one manual local extraction step but no new runtime architecture; the provider already checks the bundled path and then the bounded per-user model path. Bundling the model increases the installer by about 1.095 GB and makes every release rebuild materially slower, so the optional package is the accepted 0.0.9 layout.
